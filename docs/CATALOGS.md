# كتالوجات المنتجات للصفحات — دليل التشغيل

> كل صفحة ماسنجر تجيب من كتالوجها النشط فقط — بالمعرف الموثوق من مسار
> الرسالة، لا باسم الصفحة ولا بكل منتجات القاعدة.

## الموديلات (ترحيل `20261012120000_page_catalogs` — إضافي فقط)

| الموديل | الدور | القيود |
|---|---|---|
| `Catalog` | مجموعة مسماة لمنتجات المساحة (اسم · وصف · نشط) | فريد لكل مساحة بالاسم |
| `CatalogProduct` | رابط كتالوج↔منتج (+ ترتيب اختياري) | فريد لكل زوج — لا تكرار |
| `CatalogPageAssignment` | الكتالوج النشط لقناة الصفحة | `channelId` فريد — صفحة واحدة = كتالوج نشط واحد، والتبديل يستبدل الصف ذريًا |

- حذف منتج من كتالوج = حذف صف الربط فقط. حذف كتالوج = حذفه وروابطه فقط.
- الأسعار والعروض والمخزون تبقى على `Product` — لا نسخة ثانية أبدًا.
- `channelId` هو صف القناة (`Channel` نوع FACEBOOK) — خلفه حساب القناة بهوية الصفحة الموثوقة.

## APIs

| المسار | الصلاحية | الوظيفة |
|---|---|---|
| `GET /api/catalogs` | catalogs.read | قائمة + بحث + فلترة + عد المنتجات/الصفحات |
| `POST /api/catalogs` | catalogs.write | إنشاء |
| `GET/PATCH/DELETE /api/catalogs/[id]` | read/write | تفاصيل + تعديل + حذف |
| `POST/DELETE /api/catalogs/[id]/products` | catalogs.write | إضافة (تخطي المكرر/الأجنبي بعدّ) / فك ارتباط |
| `POST/DELETE /api/catalogs/[id]/pages` | catalogs.assign | ربط / فك ربط (الكتالوج والمنتجات تبقى) |
| `GET /api/channels/by-id/[id]/catalog` | catalogs.read | الكتالوج النشط + معاينة المنتجات للصفحة |

كل عملية حساسة تُسجَّل بـ `AuditLog` (`catalog.created/updated/deleted/products_added/product_removed/page_assigned/page_unassigned`).

## كيف يختار AI المنتجات

1. الرسالة تصل → المحادثة تحمل `channelId` الموثوق.
2. `resolveCatalogForChannel` (المكان الوحيد) يقرأ الكتالوج النشط.
3. مطابقة المنتجات تنحصر بمنتجات الكتالوج (`id: { in }`).
4. بلا كتالوجات بالمساحة إطلاقًا = السلوك القديم حرفيًا. بكتالوجات وصفحة بلا إسناد = لا منتجات (يُعرض بالواجهة صراحة).

## إنشاء كتالوج وربطه (للمالك)

1. «كتالوجات المنتجات» ← «إنشاء كتالوج جديد» ← سمِّه وصفْه.
2. من التفاصيل: «إضافة منتجات» (بحث + تحديد متعدد + معاينة) ثم «ربط الصفحة».
3. أو من صفحة القناة: قسم «كتالوج المنتجات» ← «تبديل» (بتأكيد).
4. زر «معاينة الكتالوج» = نفس ما سيستخدمه الذكاء (السعر والصور والعروض حيّة من المنتج).

## النشر والتراجع

- الترحيل إضافي فقط (`CREATE TABLE` + فهارس + مفاتيح) — يُطبَّق بـ `prisma migrate deploy` (يثبته CI على Postgres حقيقي).
- كُتب يدويًا بنمط ترحيلات الريبو (لا Postgres محليًا لتوليده آليًا) — راجعه CI قبل الدمج.
- التراجع: احذف صفوف `CatalogPageAssignment` ثم `CatalogProduct` ثم `Catalog` (أو احذف مجلد الترحيل قبل تطبيقه) — لا شيء آخر يعتمد عليها.

## قيود قائمة

- الربط لقنوات ماسنجر (FACEBOOK) المتصلة فقط — لا إنستغرام/واتساب/تيليجرام بهذه المرحلة.
- بلا أسعار خاصة بالكتالوج — السعر الأصلي دائمًا (قرار موثق: لا مصدر ثانٍ).
- حذف الكتالوج مسموح دائمًا (لا شيء يشير إليه خارج روابطه) مع تأكيد وسجل.
